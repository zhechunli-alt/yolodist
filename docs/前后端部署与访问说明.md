# 前后端部署与访问说明

这份文档用于把当前仓库中的 Flask 前后端演示系统快速部署起来，并在局域网内通过其它机器访问。

## 1. 演示模型

当前默认演示模型为：

- `student_epfa`

原因：

- 它是论文主线中最具代表性的轻量改进模型
- 相比 `student_plain` 有稳定提升
- 比 `baseline` 更适合作为“轻量部署”演示

后端也支持切换：

- `baseline`
- `student_plain`
- `distill_epfa`
- `teacher_deeppcb`

只要权重文件存在于 `weights/` 中，页面就会自动显示可切换模型。

## 2. 一键启动

在项目根目录执行：

```bash
source /root/workspace/.venv/bin/activate
bash tools/deploy_backend_demo.sh
```

默认会做这些事：

1. 同步标准权重别名
2. 做后端依赖与权重预检查
3. 以 `0.0.0.0:18080` 启动 Flask 服务
4. 输出日志与 PID 文件

启动成功后，日志在：

- `runs/service_logs/backend_demo.log`

PID 文件在：

- `runs/service_logs/backend_demo.pid`

停止服务：

```bash
bash tools/stop_backend_demo.sh
```

## 3. 本机访问

浏览器打开：

```text
http://127.0.0.1:18080
```

健康检查：

```bash
curl http://127.0.0.1:18080/api/v1/health
```

模型列表：

```bash
curl http://127.0.0.1:18080/api/v1/models
```

## 4. 其它机器访问

当前服务器局域网 IP：

- `10.18.207.22`

如果其它机器和这台服务器网络互通，可直接访问：

```text
http://10.18.207.22:18080
```

如果访问失败，按顺序检查：

1. 服务是否已启动
2. 服务器安全组或防火墙是否放行 `18080`
3. 其它机器是否和服务器在同一局域网或可达网络

## 5. 当前前后端能力

页面已支持：

1. 上传单张图片
2. 加载文件夹中的图片
3. 模型切换
4. 单模型检测
5. 多模型对比
6. 统计结果查看
7. 人工复核信息保存
8. 历史记录查看
9. 导出 JSON 质检报告

## 6. 演示建议

如果用于现场演示，建议按这个顺序：

1. 页面打开后先确认右上角服务状态为“服务正常”
2. 保持默认模型 `student_epfa`
3. 上传一张典型 PCB 缺陷图片
4. 先做单模型检测
5. 再切换到“多模型对比”查看不同模型的结果差异
6. 最后填写人工复核意见并导出 JSON 报告

## 7. 注意事项

1. 当前前后端是演示部署，使用 Flask 自带服务，适合论文展示和局域网访问，不是生产级部署
2. 如果后续需要公网长期运行，建议换成：
   - `gunicorn + nginx`
   - 或单独拆前后端服务
3. 当前页面模板已经改成 PCB 质检语境，但数据库表名仍保留了早期 `review_notes` 等字段名，这不影响实际使用
