# 前后端部署与访问说明

这份文档只负责说明**当前真实可用**的 PCB 演示系统：如何启动、如何访问、系统能做什么、当前有哪些模型可以在线运行、数据库和文件落盘在哪里，以及如果外部访问失败应该怎么排查。

---

## 1. 当前系统定位

当前系统是一个基于 Flask 的 PCB 缺陷检测演示平台，服务于：

- 论文截图与答辩演示
- 单图检测与批量检测演示
- 主线模型与非 YOLO 经典模型的单图在线对比
- 检测记录保存与人工复核

它不是生产级部署，而是**论文与实验演示系统**。

---

## 2. 当前默认模型与可在线模型

### 2.1 默认演示模型

当前默认模型：

- `DeepPCB / Student-EPFA`

原因：

- 它是论文主线中最具有代表性的轻量改进模型。
- 精度明显优于 `student_plain`。
- 参数量仅 `1.286M`，适合展示“轻量但有效”的主旨。

### 2.2 当前可在线运行的主线模型

#### DeepPCB

- `DeepPCB / Student-Plain`
- `DeepPCB / Student-EPFA`
- `DeepPCB / Distill-Plain`
- `DeepPCB / Distill-EPFA`
- `DeepPCB / Teacher-YOLO11n`

#### PKU-Market-PCB

- `PKU / Student-Plain`
- `PKU / Student-EPFA`
- `PKU / Distill-Plain`
- `PKU / Distill-EPFA`
- `PKU / Teacher`

#### DsPCBSD+

- `DsPCBSD+ / Student-Plain`
- `DsPCBSD+ / Student-EPFA`
- `DsPCBSD+ / Distill-Plain`
- `DsPCBSD+ / Distill-EPFA`
- `DsPCBSD+ / Teacher`

### 2.3 当前可在线运行的非 YOLO 对比模型

当前 DeepPCB 对比模型中，下面这批已经接入在线推理，并能进入 `多模型对比` 工作区：

- `FasterRCNN-MNV3-FPN`
- `RetinaNet-R50-FPN`
- `FCOS-R50-FPN`
- `FasterRCNN-R50-FPN`
- `FasterRCNN-R50-FPN-v2`

说明：

- 这批模型使用独立的 `torchvision` 在线推理链路，不再只是静态论文资产。
- 后端已经统一输出格式，因此前端能够直接显示：
  - 检测叠加图
  - 检测框列表
  - 置信度统计
  - 推理耗时

## 3. 启动方式

### 3.1 推荐方式

在项目根目录执行：

```bash
cd /root/workspace/yolodist
source /root/workspace/.venv/bin/activate
python -m service.backend.app
```

默认监听：

- `0.0.0.0:18080`

### 3.2 本机检查

## 4. 当前访问地址

### 4.1 本机访问

- `http://127.0.0.1:18080`

### 4.2 校园网 / 局域网访问

- `http://10.18.207.22:18080`

### 4.3 Tailscale 访问

当前可用 Tailscale 地址：

- `http://100.101.23.89:18080`

注意：

- 旧地址 `100.102.5.1`、`100.77.64.13` 都已失效。
- 不要再缓存旧 IP。

### 4.4 如果 Tailscale 再次掉线

当前环境没有 `/dev/net/tun`，且缺乏正常 `iptables/netlink` 权限，因此 Tailscale 需要以 `userspace-networking` 模式运行。

当前状态查询命令：

```bash
tailscale --socket=/tmp/tailscaled.sock status
```

若后续再掉线，优先检查：

1. 后端本身是否正常：

```bash
curl http://127.0.0.1:18080/api/v1/health
```

2. Tailscale 是否仍在线：

```bash
tailscale --socket=/tmp/tailscaled.sock status
```

如果后端正常但 Tailscale 不通，通常不是 Flask 挂了，而是 Tailscale 连接掉了。

## 5. 当前页面结构

页面已经整理成 4 个模块页，尽量避免长滚动，适合论文截图。

### 5.1 数据加载

功能：

- 单张图片导入
- 文件夹导入
- 三个数据集样本的一键导入

当前内置样本集：

- `DeepPCB`
  - 单张样本
  - 小样本文件夹
- `PKU-Market-PCB`
  - 单张样本
  - 小样本文件夹
- `DsPCBSD+`
  - 单张样本
  - 小样本文件夹

等待交互：

- 已增加 `数据载入中` 弹窗，避免静默等待。

### 5.2 单模型检测

功能：

- 按数据集选择主线模型
- 当前图片检测
- 整个文件夹检测
- 暂停检测
- 上一张 / 下一张浏览
- 图片选择列表（每页 `5` 张）
- 已检测 / 检测中 / 未检测状态标记

逻辑特性：

- 文件夹检测时，前端不会自动切换当前显示图片。
- 用户当前查看哪张，界面就一直显示哪张。
- 如果查看一张已检测图片，会恢复其检测框与结果。
- 如果查看一张未检测图片，会显示“尚未检测”状态。

### 5.3 多模型对比

功能：

- 只对**当前选中的单张图片**做多模型对比
- 顶部按数据集切换主线模型
- 工作区两列展示
- 每个结果卡片显示：
  - 模型名
  - 耗时
  - 检测数
  - 最高置信度
  - 平均置信度
  - 检测叠加图
  - 原始检测框数据

当前行为：

- 上方主线模型由用户勾选。
- 下面 `其它对比模型` 只展示名字，不额外套框。
- 当前数据集对应的其它对比模型会自动加入对比，不需要额外勾选。

### 5.4 记录导出

功能：

- 历史记录刷新
- 历史记录列表浏览
- 当前图片回看
- 原图 / 叠加图 / 检测列表展示
- 人工复核查 / 改 / 保存
- 当前记录 JSON 导出

## 6. 当前缓存与状态逻辑

### 6.1 前端图片缓存

前端导入文件夹时，会把全部图片作为浏览器 `File` 对象保存在：

- `state.files`

当前选中的图片保存在：

- `state.selectedFile`

注意：

- 这里保存的是图片文件对象本身，不是索引。

### 6.2 图片状态

当前图片状态有 3 种：

- `idle`：未检测
- `running`：检测中
- `done`：已检测

状态显示已经在所有图片选择列表里统一：

- 灰色：未检测
- 黄色：检测中
- 绿色：已检测

### 6.3 状态按模型隔离

这是当前系统非常重要的一点。

每个模型都有自己独立的：

- 图片状态
- 检测结果
- 记录 UUID
- 人工复核内容

也就是说：

- 用 `Student-EPFA` 跑过的图片，只算这个模型自己的状态。
- 切换到 `Distill-EPFA` 后，会看到它自己的检测状态，而不是沿用前一个模型。

### 6.4 文件夹检测规则

当前逻辑如下：

- 如果未切换模型：
  - 点击“检测整个文件夹”时，只处理：
    - `未检测`
    - `检测中`
  - 跳过已检测图片
- 如果切换了模型：
  - 点击“检测整个文件夹”时，对当前文件夹**全部图片从头到尾重新检测**

### 6.5 暂停检测

当前支持 `暂停检测`。

行为是：

- 不会强行打断当前这张正在跑的图
- 会在当前图结束后停止后续检测

## 7. 后端数据库与文件持久化

### 7.1 数据库类型

- `SQLite`

数据库文件：

- `/root/workspace/yolodist/service/backend/data/inference_logs.db`

### 7.2 表结构

当前主要 4 张表：

1. `inference_logs`
   - 每次推理日志
2. `inspection_records`
   - 每张图的正式检测记录主表
3. `detection_items`
   - 每条记录中的检测框明细
4. `review_notes`
   - 人工复核内容

### 7.3 什么时候落库

1. 每次真正跑推理时：
   - 写 `inference_logs`
2. 点击 `检测当前图片` 或 `检测整个文件夹` 并获得结果后：
   - 自动写 `inspection_records`
   - 自动写 `detection_items`
3. 点击 `保存复核` 时：
   - 写或更新 `review_notes`

### 7.4 上传图片副本

后端会把上传图保存到：

- `service/backend/data/uploads/`

因此系统不是只有前端缓存，而是：

- 前端有会话级缓存
- 后端有 SQLite 记录库
- 后端有上传文件副本

## 9. 当前最适合演示的方式

如果你需要做论文截图或答辩演示，推荐顺序：

1. 打开 `数据加载`
2. 直接点击某个数据集的：
   - `载入单张样本`
   - 或 `载入小样本文件夹`
3. 进入 `单模型检测`
4. 使用：
   - `DeepPCB / Student-EPFA`
5. 先做单图检测，截图主线结果
6. 再切到 `多模型对比`
7. 对同一张图运行主线模型 + 其它对比模型
8. 最后进入 `记录导出` 展示人工复核与 JSON 导出

## 10. 当前不建议误解的点

1. 当前系统的“服务状态”与“任务状态”是分开的。
   - 服务状态看 `/api/v1/health`
   - 任务状态看当前检测流程

2. 当前 `导出质检报告(JSON)` 导出的只是**当前选中的单条记录**，不是整个文件夹的所有记录。

3. `多模型对比` 只支持**当前图片**，不支持整个文件夹批量对比。

4. 其它对比模型已经可以进入在线多模型对比，但它们主要是 `DeepPCB` 的非 YOLO 经典模型，不要误写成“所有数据集的所有对比模型都在线支持”。
