# DeepPCB 新增对比模型方案

## 当前项目状态

当前主线最重要的轻量模型是 `student_epfa`：

- 参数量：约 `1.286M`
- DeepPCB `test`：
  - `Precision = 0.9438`
  - `Recall = 0.9156`
  - `mAP50 = 0.9633`
  - `mAP50-95 = 0.6984`

这轮新增对比的目标不是去找更强的大模型，而是补充一组：

- 非 YOLO 为主
- 有工程代表性
- 参数量不要大得离谱
- 结果最好整体略弱于 `student_epfa`

## 候选模型池

### 1. SSDLite320-MobileNetV3-Large

- 约 `3.79M` 参数
- 轻量、工程常见、部署导向强
- 适合作为明显偏弱的轻量非 YOLO 基线
- 接入难度低，当前仓库已支持
- 预期表现：明显弱于 `student_epfa`

### 2. Faster R-CNN MobileNetV3 Large 320 FPN

- 约 `18.96M` 参数
- 非 YOLO、two-stage，有较强代表性
- 比 SSDLite 更稳，但仍不属于过重的上界模型
- 对 PCB 缺陷这种小目标检测任务有一定适配性
- 接入难度低，只需扩展 `torchvision` 支持
- 预期表现：弱于或接近 `student_plain`

### 3. Faster R-CNN MobileNetV3 Large FPN

- 约 `18.96M` 参数
- 比 320 版更强，仍保持非 YOLO 和较清晰的论文解释价值
- 适合作为“中等强度的非 YOLO 对比模型”
- 接入难度低
- 预期表现：接近 `student_plain` 或略低于 `student_epfa`

### 4. EfficientDet-D0

- 参数量通常在 `4M` 左右
- 从任务属性上比较适合工业视觉
- 但当前仓库没有现成接入基础，训练和评估都需要额外适配
- 接入风险中等偏高
- 本轮暂不优先

### 5. RT-DETR / DINO / Deformable DETR 小配置

- 方法学上有代表性
- 但实现、训练和调参成本高
- 结果容易变成太强的上界，不符合本轮“合理但略弱”的目标
- 本轮不优先

### 6. RetinaNet / FCOS ResNet50

- 当前仓库已有接入基础
- 但参数量明显偏大，且之前实验显示 DeepPCB 上结果偏强
- 不适合本轮作为“接近学生模型”的主对比对象

## 最终入选模型

本轮实际执行的新增模型为：

1. `SSDLite320-MobileNetV3-Large`
2. `Faster R-CNN MobileNetV3 Large 320 FPN`
3. `Faster R-CNN MobileNetV3 Large FPN`

后续又补充并完成了以下经典强基线：

4. `RetinaNet-R50-FPN`
5. `FCOS-R50-FPN`
6. `Faster R-CNN ResNet50 FPN`
7. `Faster R-CNN ResNet50 FPN v2`

## 入选理由

1. 都是非 YOLO 系列。
2. 都是常见、可复现、论文里容易解释的检测器。
3. 都能直接基于当前仓库的 `comparison` 框架落地，不需要大重构。
4. 结果区间更可控，不太容易出现“远强于 student_epfa 抢走主线”的情况。
5. 三者层次清晰：
   - `SSDLite`：弱轻量基线
   - `Faster R-CNN 320`：中等强度基线
   - `Faster R-CNN FPN`：更强一些的非 YOLO two-stage 基线

## 统一实验设置

全部采用：

- 数据集：`DeepPCB`
- 输入尺寸：`640`
- 训练轮数：`100`
- 随机种子：`42`
- 优化器：`SGD`
- 学习率：`0.005`
- `momentum = 0.9`
- `weight_decay = 5e-4`
- 评价指标：
  - `Precision`
  - `Recall`
  - `mAP50`
  - `mAP50-95`

说明：

- 这批新增非 YOLO 对比模型走的是 `torchvision` 检测框架。
- `mAP50` 与 `mAP50-95` 使用 `torchmetrics.detection.MeanAveragePrecision` 计算。
- `Precision` 为在 `IoU=0.5`、`score_threshold=0.25` 下的全局匹配精度，用于补齐 `torchvision` 对比线的汇总表字段。

不同点仅在 batch：

- `SSDLite320-MobileNetV3-Large`: `batch = 16`
- `Faster R-CNN MobileNetV3 Large 320 FPN`: `batch = 8`
- `Faster R-CNN MobileNetV3 Large FPN`: `batch = 6`

## 当前执行结果

三条新增 DeepPCB 对比模型均已完成训练和正式 `test` 评估。

| 模型 | Params(M) | Precision | Recall | mAP50 | mAP50-95 | 推理 FPS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `student_epfa` | 1.286 | 0.9438 | 0.9156 | 0.9633 | 0.6984 | 558.63 |
| `SSDLite320-MobileNetV3-Large` | 3.792 | 0.3433 | 0.3239 | 0.1889 | 0.0518 | 233.26 |
| `Faster R-CNN MobileNetV3 Large 320 FPN` | 18.956 | 0.5647 | 0.2859 | 0.5606 | 0.1881 | 174.43 |
| `Faster R-CNN MobileNetV3 Large FPN` | 18.956 | 0.8537 | 0.7361 | 0.9243 | 0.6643 | 164.93 |

## 结果解释

### 1. SSDLite320-MobileNetV3-Large

- 结果明显弱于 `student_epfa`
- 适合作为“轻量但检测能力偏弱”的非 YOLO 基线
- 论文里可用于说明单纯依赖轻量通用检测器不足以覆盖 PCB 小缺陷需求

### 2. Faster R-CNN MobileNetV3 Large 320 FPN

- 结果也明显弱于 `student_epfa`
- 说明 two-stage 框架即使换成 MobileNet 主干，在当前任务上仍没有形成足够强的性能
- 适合做“非 YOLO two-stage 中等基线”

### 3. Faster R-CNN MobileNetV3 Large FPN

- 这组三项指标里最有价值
- `mAP50-95 = 0.6643`，已经比较接近 `student_epfa = 0.6984`
- 但整体仍低于 `student_epfa`
- 非常适合放进论文主表，因为它满足：
  - 非 YOLO
  - 常见检测框架
  - 有代表性
  - 结果略弱于我们的方法

### 4. RetinaNet-R50-FPN / FCOS-R50-FPN

- 这两条线在 DeepPCB 上属于“更强但更重”的经典 one-stage 基线。
- 它们的主要价值不在于证明我们精度全面更好，而在于支撑下面这条论文叙事：
  - 我们的方法更轻、更适合资源受限部署；
  - 更大的经典检测器可以换来更高的 `mAP50-95`，但代价是显著更大的参数规模与更低的吞吐。

### 5. Faster R-CNN ResNet50 FPN / v2

- 这两条线是当前最像样的强 two-stage 基线。
- 它们不是“略弱于我们”的那类对比，而是“经典 strong baseline”。
- 推荐写法：
  - `FasterRCNN-MNV3-FPN` 放主表，体现“合理且略弱”的非 YOLO 对比；
  - `FasterRCNN-R50-FPN / v2` 放补充主表或附录，体现“强基线更大更重”。

## 论文写作价值判断

如果只保留一组新增非 YOLO 对比模型，最建议保留：

- `Faster R-CNN MobileNetV3 Large FPN`

如果保留三组完整梯度，则建议写成：

1. `SSDLite320-MobileNetV3-Large`
2. `Faster R-CNN MobileNetV3 Large 320 FPN`
3. `Faster R-CNN MobileNetV3 Large FPN`

这种排列可以形成：

- 弱轻量基线
- 中等 two-stage 基线
- 较强 two-stage 基线

从而更清晰地体现 `student_epfa` 的优势。

## 后续补充的强基线

后续又补跑并完成了两类更经典的强基线：

1. `RetinaNet-R50-FPN`
   - `Params = 36.456M`
   - `Precision = 0.8046`
   - `Recall = 0.8055`
   - `mAP50 = 0.9681`
   - `mAP50-95 = 0.7547`

2. `FCOS-R50-FPN`
   - `Params = 32.129M`
   - `Precision = 0.8093`
   - `Recall = 0.8163`
   - `mAP50 = 0.9498`
   - `mAP50-95 = 0.7532`

这两条线都说明：

- 更大的经典检测器在 DeepPCB 上可以取得高于 `student_epfa` 的 `mAP50-95`
- 但代价是模型规模和推理开销明显更高

因此论文里更合理的写法是：

- `Faster R-CNN MobileNetV3 Large FPN` 作为“略弱于我们”的代表性非 YOLO 对比
- `RetinaNet-R50-FPN / FCOS-R50-FPN / Faster R-CNN ResNet50 FPN` 作为经典强基线，用于支撑“我们的模型更轻、更适合资源受限部署”这一叙事

## 在线演示系统中的对比模型现状

当前 Web 演示系统中，DeepPCB 的以下非 YOLO 对比模型已接入在线推理：

- `FasterRCNN-MNV3-FPN`
- `RetinaNet-R50-FPN`
- `FCOS-R50-FPN`
- `FasterRCNN-R50-FPN`
- `FasterRCNN-R50-FPN-v2`

说明：

- 这些模型不再只是“静态论文资产”。
- 后端已经为 `torchvision` 检测器补了一套在线推理接口。
- 在 `多模型对比` 页面中，它们会作为 `DeepPCB` 的“其它对比模型”自动加入对比工作区。
- 输出已统一为与主线 YOLO 模型相同的前端格式，因此可以显示：
  - 检测叠加图
  - 原始检测框数据
  - 耗时
  - 检测数
  - 置信度统计

这部分更适合写进：

- 系统实现章节
- 演示平台说明
- 论文附录中的可视化对比说明
